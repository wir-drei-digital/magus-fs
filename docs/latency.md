`python3 tests/fs2/latency.py --image sha256:IMMUTABLE_IMAGE_ID --output NEW_ABSOLUTE_PATH --phase wakeups` runs one owned synthetic diagnostic. Use a release image built from the frozen checkout with `tests/fs2/Dockerfile.linux`, `VERIFY=latency`, `BUILD_PROFILE=release`, `BIN_DIR=release`, and matching host release default/fault executables. The driver independently compares every runtime/test source with the image and records source/binary/image identities.

The wakeups phase measures 12 mounted saves each on small and warm 64 MiB backgrounds, rotating 24 B, 1 KiB and 16 KiB. Both engines use a fresh owned named disk volume for replica state; ordinary writes/read sampling execute as UID/GID 1001. There are three native saves per background and an atomic editor-save smoke. Linux processes share the VM CLOCK_MONOTONIC clock; native host/VM differences are reported as first-read upper bounds, never subtracted as cross-clock stages. This is a diagnostic in one mounted container, not the two-container final acceptance cohort or host/VM power-loss qualification.

`MAGUS_LATENCY_TRACE=1` opts into bounded-line diagnostics for durable admission, private/shared local receipts, service postcommit, authenticated discovery and successful exact Applied acknowledgement. Events carry operation/revision/head IDs and monotonic nanoseconds, without content, paths or credentials. Sender local and peer projected revision IDs may differ; the driver binds the exact peer projection to the Shared receipt head. It requires the exact service integration operation/head stamp and exact peer Applied revision/head before reporting end-to-end completion; completion is the latest of Shared commit, Applied and fresh ordinary read. Sender receipt recording may occur after peer discovery. Publisher execution-gate wait is logged separately. Public status still performs integrity checks; diagnostics do not change acknowledgement semantics.

Separate untimed boundary checks cover dropped authenticated hints with durable fallback, transport reconnect, current credential revocation/socket close, isolated private-only publication and readonly mutation denial. Raw timed attempts, transient errors, stages, receipt/base bindings, fixture hashes, source/image proofs and owned normal-unmount/resource cleanup remain in the private output. Failed attempts remain failures. Keep existing cache and prior evidence; never relabel an old image with new source.

Process-local publisher and incoming advisory epochs are shared per replica and carry no data. Durable successful admission signals publisher; authenticated WS cursors signal incoming. A 1-second fallback retains replay and authority refresh. Service subscribers register before reading their authorized durable page, then reauthorize on hints/fallback. Seed, integration (including validated integration), resolution and restore signal after committed Shared publication. No hint substitutes for durable data or current authorization. Multi-service-process notification delivery remains a later scope.

Mounted generation coalescing is 25 ms with 50 ms metadata observation; native integrity scans remain at 2 seconds. Native capture uses the conservative content-reuse path below.

For an affected rerun, `--skip-boundaries` and `--skip-native-small` omit explicitly unchanged scenarios. The output labels these as not-run; prior evidence and its source bridge must be retained separately. These flags do not qualify omitted cases on new source.

## Conservative content reuse (Task2, ruling L2)

Use `--phase reuse` with a source-matched release image built using `VERIFY=reuse`; workload sizes, disk state, receipt/base bindings and exact Shared/Applied/fresh-read assertions are unchanged. Native rows additionally bind `object_work` counters to the exact local capture revision. Counters record source bytes read, object bytes verified, staged bytes/stages, attempted file/directory barriers and inventory scans. Read and sync costs remain visible; this phase does not claim zero work for unchanged objects.

An existing object is opened without following links and fully read/hash/size/private-mode verified. Public `ObjectStore::install` skips duplicate staging, but still completes a file and anchored-directory sync before returning. New objects retain the original verified staging, file sync, atomic no-replace link, directory sync, staging unlink and directory sync. Legitimate multiple-link publication retains the verified slow path. Public reads and deep status always verify bytes.

Within one Core-locked native capture, a private preparation helper verifies existing content without claiming durable acceptance. Final closure processing freshly verifies and syncs **every** referenced object, then syncs the anchored object directory once before the capture journal transaction. Checkpoint closure processing shares that directory barrier while preserving the existing missing/refetchable-object checks. SQLite WAL/FULL/Mac fullfsync, service/backend durability, authority checks, original operation/base and native recovery semantics are unchanged.

Capacity uses one inventory snapshot per capture attempt, including abandoned stage bytes, with checked known additions. The actual occupied inventory is reconciled again before acknowledgement. The snapshot never survives the attempt/Core lock; GC, protected roots and other operations' reservation APIs retain their original behavior. External excess stages, missing content and corruption cannot produce a new capture acknowledgement.

There is no durability-proof cache or retained object-FD cache. A rejected prototype cached verified hash/durability against inode/metadata identity; Linux tests showed immediate same-size overwrites retain identical coarse mtime/ctime, and a macOS MAP_SHARED mutation also escaped that proof. Metadata equality therefore cannot establish immutable content. The approved conservative fallback preserves fresh verification and file barriers; neither age heuristics nor filesystem event assumptions replace them. Same-byte truncate/rewrite is also required to cross a new barrier. The rejected prototype's failed build and diagnostic evidence remain retained, without a release-image or timing claim.

## Pooled transport and final cohort procedure

HTTP transport keeps its synchronous caller interface. A weak registry shares one ordinary-thread executor per replica while controller/incoming/registered source owners remain alive. Admission allows at most16live executors; each has four active requests,32queued jobs and eight LRU clients. A32MiB budget covers actual retained bodies across queue and active work, with immediate release when a queued deadline expires; canonical revision bodies retain their16MiB limit and JSON control bodies retain64KiB. Each client retains at most two idle connections per host for30seconds. Clients preserve pinned trust, no proxy, no redirects and no retry; authorization is attached to each request after private profile/CA/token validation both at enqueue and dispatch. Changes to profile/trust/token invalidate that profile's cached compatible client. A request's absolute deadline covers queue time, connection and response body; the reusable client has a fixed two-second connection bound and no first-request-derived total timeout.

The executor never obtains Core/adapter locks or calls Replica. Existing synchronous demand fetching still runs under the existing bounded Core authorization/generation protocol; this change does not qualify lock-free or cold500ms reads. Actual blocking DNS holds one of four global permits until lookup returns, even after a request timeout/runtime teardown. DNS admission failures carry their own typed error through that request's error chain, without shared stale exhaustion state. Jobs and workers own no executor Arc. Last-owner drop cancels queued/active work, waits at most100ms for worker completion, then detaches if necessary; runtime shutdown never joins stalled DNS.

Build with `VERIFY=pooled BUILD_PROFILE=release BIN_DIR=release` using `tests/fs2/Dockerfile.linux`, retaining warm build caches and inspecting available VM disk first. Match the default/fault host release executables and all five Linux binaries to frozen source hashes. `--phase pooled` retains the prior12-mounted/three-native-per-background diagnostic and runs real hint-drop/reconnect/current-grant/readonly/isolated boundaries. `--phase acceptance` runs one fresh owned cohort; invoke it twice with separate new absolute output directories against the same immutable image. It creates separate sender/receiver sandbox containers with independent VM-disk volumes and ordinary UID/GID1001 saves/reads.

Mounted completion is the latest of exact service Shared commit, projected peer Applied acknowledgement and exact ordinary fresh read on the VM monotonic clock. Native completion is a host-observed upper bound through those exact bindings; host and VM clocks are never subtracted. Structural/unknown native retained-root recovery remains the existing slower safe path.
