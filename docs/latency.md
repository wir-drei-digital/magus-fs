## Pooled transport and final cohort procedure

HTTP transport keeps its synchronous caller interface. A weak registry shares one ordinary-thread executor per replica while controller/incoming/registered source owners remain alive. Admission allows at most16live executors; each has four active requests,32queued jobs and eight cached compatible LRU clients. Up to four active request client clones may outlive cache eviction. A32MiB budget covers actual retained bodies across queue and active work, with immediate release when a queued deadline expires; canonical revision bodies retain their16MiB limit and JSON control bodies retain64KiB. Each client retains at most two idle connections per host for30seconds. Clients preserve pinned trust, no proxy, no redirects and library retry-never; authorization is attached to each request after private profile/CA/token validation both at enqueue and dispatch. Changes to profile/trust/token invalidate that profile's cached compatible client. A request's absolute deadline covers queue time, connection and response body; the reusable client has a fixed two-second connection bound and no first-request-derived total timeout.

The executor never obtains Core/adapter locks or calls Replica. Existing synchronous demand fetching still runs under the existing bounded Core authorization/generation protocol; this change does not qualify lock-free or cold500ms reads. Actual blocking DNS holds one of four global permits until lookup returns, even after a request timeout/runtime teardown. DNS admission failures carry their own typed error through that request's error chain, without shared stale exhaustion state. Jobs and workers own no executor Arc. Last-owner drop cancels queued/active work, waits at most100ms for worker completion, then detaches if necessary; runtime shutdown never joins stalled DNS.

Immutable remote object fetching explicitly handles service admission contention: only an actual HTTP503 with JSON `code: backpressure` permits another GET on the identical view/object path. A private error origin distinguishes this response from local queue/body/DNS pressure. The fetch fixes one absolute deadline at the earlier of the caller's deadline and its initial time plus4.5seconds. Each wait is at most25ms, clipped to that deadline; every new attempt validates private profile/CA/token again and the service checks current authority. Actual repeated GET dispatches increment `retries`. POSTs and other transport APIs retain one attempt, and denial, missing content, corruption, changed trust, other503s and local admission failures remain terminal. Native baseline hydration shares this boundary while retaining its60second aggregate budget; persistent or overdeadline pressure can still terminate default native startup. Fixture supervision, absent from the default CLI, permits at most three starts per created native client inside its original60second setup budget only after an exited classified-pressure process; all original PIDs/errors remain evidence.
