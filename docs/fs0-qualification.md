Output must be an absolute, new path with an existing parent. The runner creates one `result.json` plus six owned Linux profile directories, each with raw commands/stdout/stderr, original and projected manifests, image/OS/capability facts and cleanup evidence. Exit0 means all selected platform gates passed; exit1 means an observed case, manifest, freshness or cleanup failure; exit2 means missing or blocked evidence. `--platform linux` scopes qualification to Linux only. `--platform macos` currently records the prerequisite block without invoking `macos_run.py`; Mac mounting remains disabled in this runner pending the controller-reviewed diagnostic and native qualification.

The versioned report schema is `magus-fs-fs0-result-v1`. Required profiles are journeys1/2 × chunk sizes65536/262144/1048576 for every selected platform. Each mandatory case includes state, expected, observed and actual command. Aggregation rejects absent platforms/profiles/cases/commands, differing manifest identities at the same chunk size, reused owned tokens, missing/stale counters and leaked resources. Failures take precedence over prerequisite blocks. A profile cannot pass from the child runner's exit code alone.

Each Linux profile creates a new Rust fixture source, projection endpoint, private overlay and actual FUSE mounts, then checks source body counters before other workloads hydrate the view. Enumeration must fetch zero bodies. Exact4KiB head/tail reads of64MiB must fetch at most8MiB including readahead and repeated source requests; a warm repeat must add zero. A streamed ordinary-process full scan must match SHA-256 generated separately from the synthetic byte formula and report the actual source transfer. Chunk size is an experiment, not a production layout decision.

Normal virtual entries explicitly use UID/GID501:20, constructed by a test-only metadata proxy over the real Rust source. The proxy preserves all paths/modes/sizes/descriptors, verifies the original canonical digest, recomputes the projected digest and serves the original verified chunks. Reports retain both identities and the construction actor. Independent endpoints are acceptable only after their actual manifests have the same verified digest; Mac default501:20 and Linux physical0:0 source digests are never treated as equal. Native Mac equality remains unproved. Source files can inherit their group from the chosen parent: the controller observed a501-owned Mac fixture under `/private/tmp` with GID0, whereas the original user-temp parent yielded GID20. Process `getgid` does not prove fixture ownership; verify actual manifest IDs/digest or use explicit fixture projection. Root UID/GID0:0/mode0755 is observed separately on Linux: the root is mapped to the daemon principal and is outside the FS0 manifest digest. FS1 must bind root metadata in its durable format.

Counters are original Rust source response payloads. `content_body_bytes` includes all served chunk bodies and repeated requests. `retry_requests` counts repeated hash requests, not inferred client retry intent. `metadata_bytes` counts original Rust manifest bodies and excludes projected proxy responses, stats/control traffic and network framing. Reports record the projected manifest response length separately; they do not claim a measurement of all client/network metadata legs.
