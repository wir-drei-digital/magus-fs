# FS1 local journal and working state

`magus-fs-core` now implements a durable local working branch, immutable revision metadata, lazy verified chunks, fixed logical permissions and checkpoint replay. This is the engine foundation; native FS1 mounts, native capture, materialization, export and shared publication are not implemented by this task. FS0 descriptors remain rejected. The canonical v1 format and limits remain in [fs1-format.md](fs1-format.md).

## Ownership and configuration

`Replica::open(state, config)` owns one private control directory with `owner.lock`, `journal.sqlite`, SQLite WAL/SHM, and `objects/`. **The whole control directory must be outside every selected or intended content root.** Supply the complete inventory in `ReplicaConfig.content_roots`; this uses the existing native identity/ancestry and no-follow checks. macOS scratch callers must use a canonical spelling such as `/private/tmp`. State is mode0700; ordinary control files and objects are mode0600, owned by the effective host UID. Symlinks, special files, unsafe modes/ownership and control-file hardlinks are refused. Every engine entrypoint checks that the named control directory still names its opened native directory and validates existing SQLite side files. Replacement or relocation while open fails `unsafe_storage`. Object access remains fd-anchored.

An exclusive nonblocking OS advisory lock permits **one owner process**. Opening a second owner returns `replica_busy`. `Replica` and `Workspace` clones share a mutex and one SQLite connection; all operations serialize. The lock lives until the last Replica/Workspace drops. Handles are workspace capabilities; a handle alone cannot reopen a replica. A malicious process sharing the storage UID or a host administrator is outside the isolation boundary, as in the object-store contract. SQLite uses its normal Unix pathname VFS under that private, guarded directory; it is not a custom fd-relative SQLite VFS.

There is one persistent writable branch per state root. Its selected base, current head, generation, namespace/extents, umask0022 and uncheckpointed state are durable. `begin` with its selected base or current head resumes that branch; a different base returns `base_mismatch`, even if clean. Isolated concurrent branches use different replica/state roots. Read-only historical workspaces can coexist with the working branch. Dropping and reopening never resets dirty work. Open-unlinked entries survive while their handles live; those process-local handles expire on restart.

**Adapter obligation:** a mounted daemon must remain the owner. Task4/Task5 checkpoint, status and history requests while mounted must go through an owned private control socket (or equivalent serialized control channel) to that same engine. A competing CLI owner receiving Busy does not satisfy the required mounted checkpoint journey. The Linux adapter now implements this channel; see [fs1-linux.md](fs1-linux.md).

Configuration persists exactly and must match on reopen. `ReplicaConfig` contains `replica: ReplicaId`, `authorities: Vec<Authority>`, `content_roots: Vec<PathBuf>`, `cache_bytes: u64`. Each fixed `Authority` has `principal`, host `uid`, `primary_group`, host `gid`, logical `groups`, `dac_override` and `ownership_transfer`. Principals/UIDs and the primary group/GID mapping are unambiguous. Configuration is trusted local authority; it is not a per-request credential payload. `Actor::new(PrincipalId)` selects a configured logical actor, and unknown IDs fail. Adapters must bind this to their fixed, trusted mount identity; they must not accept an arbitrary known principal ID from wire credentials. `actor_for_uid` resolves only configured UIDs and does not authenticate an incoming UID. Administrative Replica methods (import/history/pin/prune) are trusted local control APIs. Content access uses actor-bound Workspace methods.

`ImportDescriptor { expected: RevisionId, bytes: Vec<u8> }` requires the complete, canonical descriptor bytes and matching digest. Imports validate the complete tree, reject noncanonical encodings, check resident object sizes/hashes, and register descriptor/source references in one transaction. They **do not fetch missing bodies** or advance the working head. Source registrations are per ObjectId and require consistent declared sizes across every import. The latest explicit, validated Local or Http registration replaces the prior endpoint, including for repeated imports of the same revision or a shared object in another revision. Unavailable registers an absent source but never downgrades an existing endpoint. Size conflicts reject the entire import transaction without changing any registration. Endpoint registration does not fetch bodies or prove current source availability. Descriptor validity and identity do not prove residency. Missing closure is derived from the imported object/size references and verified cache inventory.

`ChunkSource` is a closed bounded abstraction: `Unavailable`, `Local { path: PathBuf }` to an existing immutable ObjectStore, or `Http { base_url: String }` to a synthetic immutable HTTP source. HTTP endpoints must use `http://<numeric SocketAddr>[/path]`, including an explicit port: for example `http://127.0.0.1:8080/objects` or `http://[::1]:8080/objects`. Hostnames, omitted ports, HTTPS and malformed URLs fail `invalid_source` before registration. The resolver parses only numeric IPv4/IPv6 addresses; it never invokes DNS. HTTP GET uses `<base_url>/<canonical ObjectId>`, no redirects, no credentials/query/fragment, and reads at most declared size+1 bytes. Every body must match its declared size and SHA-256 before installation. Local reads never create a missing source. HTTP is only the FS1 synthetic transport, not an authenticated shared-service provider. CLI/fixture callers must preserve the numeric-address restriction; FS2 authenticated HTTPS must independently qualify resolution and deadline behavior. A read shares a 4.5-second retrieval budget across all its missing chunks, leaving margin for the five-second failure requirement; a stalled/missing source returns `base_unavailable`, corruption returns `corrupt_object`. Local filesystem calls retain their normal OS I/O behavior. Individual reads/writes cap at1048576 bytes; adapters split larger requests. New write chunks use fixed262144/SHA-256. Reads ending at EOF can return fewer bytes.

Paths use the canonical relative v1 rules; `""` addresses the directory root. `list` returns immediate child names, sorted, and fetches no bodies. `lookup("")` exposes root metadata as an Entry-shaped directory record whose parent is itself; it is not a canonical tree entry. `OpenMode` is `Read`, `Write`, `ReadWrite`, or `Append` (write-only). A handle binds the workspace token, stable EntryId and opening generation; historical handles retain their exact immutable version. Mutable handles follow edits to their entry, including observed rename and unlink/replacement, without resolving a reused pathname. Handles from another workspace fail `stale_handle`. Every data operation rechecks current file authority. `create` returns a ReadWrite handle; subsequent I/O still checks the resulting mode. Append ignores supplied offset and chooses EOF under the shared lock. Truncation extension produces explicit holes. Partial writes preserve untouched chunk slices without hydrating them; reading a missing slice is an error, never an invented hole.

`Attribution { captured_at_ns: u64, coverage: Vec<String>, provenance: String }` supplies the canonical revision fields. Principal and replica are bound from the workspace/configuration, and parent is the prior head. Checkpoint records a canonical request digest binding expected generation, actor, attribution and the complete sorted tree. Identical retry returns its recorded revision before redoing side effects, including after reopen or a crash before ACK. Changed content, mode, owner or attribution with the same ID returns `operation_mismatch`. A new request with a stale generation returns `generation_mismatch`. Retry means the same current candidate; changing it before retry is intentionally a mismatch. Working mutations and checkpoint each advance generation; fsync does not create a revision.

## Journal and acknowledgment boundary

Pinned rusqlite0.40.2 uses bundled SQLite with default features disabled; Rust is1.92.0. Schema version1 is local PoC state. A newer `user_version` is rejected. Effective values are checked on open: WAL, synchronous FULL (2), foreign_keys ON (1), busy_timeout5000ms, and fullfsync ON (1) on macOS. The schema retains configuration, working state, revisions, source/size references, cache inventory, pins, operation digests/status/results and pending candidate descriptors.

Each content write installs and syncs its immutable chunks before a FULL SQLite working-state commit. Namespace and metadata changes likewise commit before success. `write` success therefore acknowledges local durable working bytes suitable for the future adapter's FILE_SYNC response; there is no delayed dirty buffer to acknowledge. `fsync` independently checks/synchronizes SQLite working state. Neither operation labels working state a revision or promises service publication. Directory/file barriers follow the existing ObjectStore contract and propagate errors. These are OS/filesystem guarantees; process-kill evidence does not prove a physical power-cut guarantee.

Checkpoint first persists its candidate and pending operation, syncs available referenced local objects, then atomically inserts the revision, records the successful operation result and advances head/generation in one IMMEDIATE transaction. Already validated lazy base references may remain missing; no full-offline claim is attached to checkpoint. A pre-commit failure preserves the prior head and acknowledged working bytes, with a pending or failed operation. Failed-operation status recording can itself encounter a real storage failure; the prior durable pending record remains the recovery evidence. A post-commit crash leaves the result available for exact replay. No file bodies enter diagnostic messages.

## Permissions, recovery and cache limits

Read-only views reject mutations before DAC override, including confined logical root. The shared evaluator implements owner/group/other rwx, current parent search versus directory listing, both rename parents, replacement rules, and writable-parent unlink of a read-only file. Directory0400 permits names-only listing but not child lookup;0100 permits lookup but not listing. Root has revision-bound metadata. Creation applies persisted umask0022. Ordinary chmod is owner-only, even for a DAC-override actor. Ownership transfer requires the explicit authority flag and allowed target group membership. Setuid/setgid/sticky modes fail `unsupported_mode`. Historical lookup, listing, open and content reads first resolve the historical entry identity, then check the current live entry's authority and current traversal path. Current grants and revocations both apply; historical ancestor modes do not veto a current grant, including after a rename. An entry no longer present is denied through a historical Workspace. A readonly imported view with no working branch yet uses its own tree for authorization. Administrative export/restore must separately enforce current destination authority in its later task; this engine does not silently restore historical permissions.

Cache limits cover published objects and interrupted staging residues. The integration fixture uses32MiB. No automatic pruning occurs: pressure returns `backpressure`, preserving prior namespace/extents. `prune(true)` reports eligible object IDs and reclaimable bytes; `prune(false)` removes eligible published objects and keeps all revision metadata/history. Eligibility is the union of genuinely unreachable garbage and clean refetchable cache objects. Reachability includes every retained revision, the current working tree, live handles (opening snapshots and current open-unlinked versions), pins and pending/failed candidate descriptors. Thus unreferenced published bodies from overwritten dirty versions or a failed save can be reclaimed even without a source; referenced local-only bodies, including committed history, remain resident. A stale serialized orphan record alone is not a root after its last handle closes. Dirty working objects, open-handle reachability, pinned full closures and **the independent descriptor closures of all pending/failed operations** additionally forbid eviction even when a source is registered. The last rule persists across restart and later working edits; Task7 prune/export and future FS2 receipts must preserve it. Interrupted stage files are conservatively counted and retained, not silently swept. Their administrative recovery/cleanup is not automated here. SQLite metadata/history bytes are separate from the configured content-cache quota.

`pin(id, true)` obtains/verifies the entire required closure before recording a recovery pin; failure does not record a complete pin. `pin(id, false)` removes only the pin. `ReplicaStatus` separates `head`, `selected_base`, `generation`, `dirty`, `resident_bytes`, `missing_bytes`, `full_ready`, `pinned`, and `operations`. Residency is reverified by hashing the cache inventory on reopen/status. Missing bytes count unique complete objects needed for the selected working tree, even when only slices are referenced. Resident bytes include other retained history/dirty objects. There is no remote-success field. Operations expose ID, pending/failed/committed state and a body-free error code.

All Task2 limits still apply:16MiB canonical descriptor,100000 entries/extents,1TiB logical files,1MiB chunks; exceeding extent count returns backpressure before installing changed chunks. Serialized mutable state additionally caps at32MiB. The engine stores the bounded namespace/extents as a transactional JSON snapshot, so mutation cost scales with this PoC tree; it is not a large-tree performance claim. The later materializer must independently check actual target filesystem collisions in addition to pinned Unicode normalization17/folding16 validation.

Errors extend the existing typed `FsError` with `database_error` (original SQLite source retained), `unsupported_schema`, `replica_busy`, `config_mismatch`, `base_mismatch`, `base_unavailable`, `invalid_source`, `backpressure`, `permission_denied`, `unknown_principal`, `read_only`, `unsupported_mode`, namespace/type errors, `stale_handle`, `generation_mismatch` and `operation_mismatch`. I/O errors retain their OS source/code. `BaseUnavailable { object, cause: SourceFailure }` retains the requested object identity and a missing/deadline/OS-I/O/HTTP-status/transport-kind cause. It does not retain response bodies or arbitrary transport error text. There are no runtime fault controls in a default build. The nondefault `test-faults` feature compiles owned-subprocess pause/ENOSPC/EIO instrumentation at object sync, pre-transaction, during transaction, DB commit and post-commit/pre-ACK boundaries, plus a five-millisecond create/handle interleaving delay. Never enable it for a deployed adapter.

## Verification scope

The four integration targets are `journal`, `working`, `permissions` and `recovery`. `recovery` with `test-faults` kills only its own unmounted worker subprocesses, reopens the actual SQLite database and checks acknowledged bytes, prior/new head, recorded operation state, replay and integrity. HTTP tests use owned loopback listeners and join their threads. Test trees are isolated TempDirs, removed after workers have exited. Host/Linux source and image provenance, exact commands, RED/GREEN evidence and cleanup are in `.superpowers/sdd/fs1-plan/task-3-report.md` and its `task-3/` artifacts. Native mount acceptance and benchmarks are not repeated or claimed by this core task.


## Native handle mutation additions

`Workspace::write_with_append(&Handle, offset: u64, bytes: &[u8], append: bool) -> Result<usize, FsError>` accepts the native descriptor's current append status. Both offset selection and durable save occur under the existing engine lock. It retains the handle identity, readonly/mode checks and current write authority; no pathname is reopened. Existing `write` behavior is unchanged and derives append from the opening OpenMode.

`Workspace::chmod_handle(&Handle, mode: u16) -> Result<(), FsError>` and `chown_handle(&Handle, owner: PrincipalId, group: GroupId) -> Result<(), FsError>` update the retained live/orphan EntryId through the same durable working transaction. Chmod requires the current logical owner; chown uses the existing configured ownership-transfer/group policy. Foreign workspace handles are stale, readonly views refuse mutations, and no removed pathname is recreated. Like native descriptor access and existing data handles, these capability methods do not re-traverse a former pathname. Path-based metadata methods retain their traversal checks.

## NFS identity and authority queries

`Workspace::retain_identity(&EntryId) -> Result<Handle, FsError>` retains an authorized file identity for transports without OPEN/CLOSE. It performs current identity/path traversal authorization without requiring data permission; it does not fetch bodies. The capability remains bound to this Workspace and actor. Read, write, truncate and metadata operations still independently enforce current rights and readonly state. This differs intentionally from `open`, whose original opening-access checks are unchanged.

`Workspace::check_access_identity(&EntryId, bits: u16) -> Result<(), FsError>` checks current traversal and rwx bits0–7 using the existing historical-current evaluator, with readonly denial for write queries. `Workspace::check_remove_identity(&EntryId) -> Result<(), FsError>` checks current writable/searchable parent authority and readonly state for NFS DELETE. Historical identities are resolved to their current parent; neither query mutates or hydrates content. The macOS adapter conservatively retains every authorized issued file handle until daemon exit; see fs1-macos.md for cache cost and session-only timestamp semantics.
